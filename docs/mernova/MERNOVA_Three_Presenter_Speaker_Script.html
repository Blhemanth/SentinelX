Our solution is anchored on four engineering pillars:

1. Zero-Bandwidth Edge Inference: Video frames never leave the local machine during normal operation. Raw pixels are ingested, buffered, and evaluated on-device using native ONNX Runtime bindings.

"Thank you, Presenter 1. Let us examine the physical inference pipeline running inside our Flutter client.

Physical camera frames are captured via DirectShow on Windows at native resolutions. These frames enter a circular TemporalFrameBuffer maintaining a sliding window of exactly 16 RGB frames. Each frame is downsampled and normalized to 224 by 224 pixels using ImageNet mean and standard deviation vectors, producing a contiguous 5D video tensor of shape [1, 16, 3, 224, 224].

In our current Phase 4.3 baseline, this is fused with a synthetic 64 by 64 acoustic silence spectrogram at minus 80 decibels, operating in a verified degraded video-only fallback mode while acoustic hardware ingestion is slated for Phase 4.4."

SLIDE 5: Thread Isolation, Memory Safety & Cryptographic Trust Boundary 1:55 – 2:20 (25 Seconds)

[Stage Action: Presenter 2 highlights the dual-isolate diagram and the security trust boundary.]

[1:55] Presenter 2 (Spoken):
"Executing a 34-million parameter deep learning model on a CPU requires roughly 1.4 seconds of intensive AVX2 compute. If executed on Flutter's main thread, the user interface would completely freeze, dropping the application to zero FPS.

To prevent this, we engineered OnnxInferenceWorker — an isolated Dart worker thread communicating via bidirectional ports. The UI thread captures camera frames and renders at a smooth 60 FPS, while the background worker independently executes ONNX C-FFI sessions.

Furthermore, our security boundary guarantees zero client trust. Client binaries contain zero HMAC secrets. Any detection submitted by a Flutter client is automatically demoted by our Express backend to an unverified 'manual_entry' state, while automated high-severity dispatches require server-to-server Protocol v2 HMAC authentication with timing-safe SHA-256 verification."
